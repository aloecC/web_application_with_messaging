# Сервис управления рассылками

## Описание проекта

Данный проект представляет собой сервис для управления рассылками, который позволяет добавлять, редактировать и удалять получателей, сообщения и рассылки. Также реализована возможность отправки сообщений по требованию и отслеживания попыток рассылок. 

## Функциональность

### 1. Управление клиентами

- Реализована возможность добавления, просмотра, редактирования и удаления получателей рассылки (клиентов).
- **Модель «Получатель рассылки»**:
  - Email (строка, уникальное) — адрес электронной почты получателя.
  - Ф. И. О. (строка) — полное имя получателя.
  - Комментарий (текст) — дополнительные сведения о получателе.

### 2. Управление сообщениями

- Реализована возможность добавления, просмотра, редактирования и удаления сообщений.
- **Модель «Сообщение»**:
  - Тема письма (строка) — заголовок сообщения.
  - Тело письма (текст) — содержание сообщения.

### 3. Управление рассылками

- Реализована возможность добавления, просмотра, редактирования и удаления рассылок.
- **Модель «Рассылка»**:
  - Дата и время начала отправки (start_time) (тип datetime) — момент, с которого рассылка может быть запущена (обязательно для заполнения).
  - Дата и время окончания отправки (end_time) (тип datetime) — момент, до которого разрешена отправка (обязательно для заполнения).
  - Статус (status) (тип строка) — динамически вычисляемый статус рассылки:
    - 'Создана' — если текущая дата раньше start_time.
    - 'Запущена' — если текущая дата между start_time и end_time (включительно).
    - 'Завершена' — если текущая дата позже end_time.
  - Сообщение (message) — внешний ключ на модель «Сообщение», определяющий, какое письмо будет отправлено в рассылке.
  - Получатели (recipients) — связь «многие ко многим» с моделью «Получатель», определяющая список клиентов, которые получат данную рассылку.
  
- **Валидация**:
  - start_time не может быть в прошлом.
  - start_time должен быть раньше end_time.

### 4. Отправка сообщений по требованию

- Реализована возможность вручную запускать рассылку через интерфейс пользователя и/или командную строку.
- **Логика работы отправки**:
  - Проверка времени: если текущее время находится между start_time и end_time, отправка разрешена; в противном случае выводится сообщение об ошибке.
  - Определение получателей: выбираются все клиенты, связанные с данной рассылкой.
  - Отправка писем: для каждого клиента выполняется отправка письма с помощью функции send_mail(). В случае успеха создается запись о попытке со статусом 'Успешно', при ошибке — со статусом 'Не успешно' и текстом ошибки.

### 5. Попытки рассылок

- Для каждой попытки отправки сообщения сохраняется следующая информация:
  - Дата и время попытки (attempt_time) (тип datetime).
  - Статус (status): 'Успешно', 'Не успешно'.
  - Ответ почтового сервера (server_response) — текст ответа от почтового сервера.
  - Рассылка (mailing) — внешний ключ на модель «Рассылка».

- Хранение истории попыток позволяет отслеживать эффективность рассылок, формировать статистику для пользователя и диагностировать ошибки доставки писем.

### 6. Главная страница

- На главной странице приложения отображаются следующие показатели:
  - Общее количество всех созданных рассылок.
  - Количество активных рассылок (текущая дата находится между start_time и end_time, а статус равен 'Запущена').
  - Количество уникальных получателей (общее число клиентов в системе).

## ЧАСТЬ 2. Расширение функциональности

### 7. Регистрация и аутентификация пользователей

- Реализована система регистрации и аутентификации пользователей.
- Пользователи могут зарегистрироваться на сайте, подтвердив свой email.
- Реализованы функции входа и выхода из системы.
- Возможность смены пароля
- Возможность восстановления пароля.

### 8. Статистика и отчеты

- Сбор и отображение информации о количестве успешных и неуспешных попыток рассылок пользователя.
- Отображение количества отправленных сообщений.

### 9. Ограничение доступа
- Пользователи могут управлять только своими рассылками и клиентами.
- Менеджеры могут просматривать все рассылки и клиентов, но не могут редактировать или удалять чужие данные.

#### Описание ролей и прав доступа:

- **Пользователь**:
  - Создание, просмотр, редактирование и удаление своих клиентов и рассылок.
  - Просмотр статистики по своим рассылкам.

- **Менеджер**:
  - Просмотр всех клиентов и рассылок.
  - Просмотр списка пользователей сервиса.
  - Блокировка пользователей сервиса.
  - Отключение рассылок.

### 10. Кеширование

- Настроено серверное и клиентское кеширование для повышения производительности.
